## Part 2 — Bug log

### BUG-1 (a) launcher source — MINOR — Landscape home screen is cramped and clips app rows
- **Repro (v0.2, either device):** rotate the home screen to landscape.
- **Observed:** the header block (brand + 48sp clock + date + search with portrait margins) consumes over half of the 1080px-tall landscape viewport; the grid is squeezed to ~1.3–1.7 rows and the second row's icons are cut mid-cell at the dock's top edge ([qa-landscape.png](sandbox://workspace/tree-os/shots/qa-landscape.png)). Everything is reachable by scrolling and nothing crashes — it is a layout defect, not a functional one.
- **Fix (v0.3):** in `MainActivity.onCreate`, when the configuration is landscape: root top padding 48→16px, clock text 48→34sp, search top margin 28→12px, grid columns 4→6.
- **Verified fixed:** v0.3 landscape shows the compact header, a 6-column grid and two complete app rows with readable labels above the dock ([qa-recheck-landscape-layout.png](sandbox://workspace/tree-os/shots/qa-recheck-landscape-layout.png) — frame includes the unrelated SystemUI ANR dialog, OBS-3; geometry at the frame edges is unobstructed).

### BUG-2 (a) launcher source — MINOR — Search query is lost on rotation
- **Repro (v0.2):** type a query in the search box (grid filters), rotate the device, look at the search box.
- **Observed (screenshot ground truth, [qa-recheck-portrait-filtered.png](sandbox://workspace/tree-os/shots/qa-recheck-portrait-filtered.png) → [qa-recheck-landscape-filtered.png](sandbox://workspace/tree-os/shots/qa-recheck-landscape-filtered.png)):** after rotation the box is **empty** (hint showing) and the grid is back to all apps. Box and grid are consistent with each other; the user's typed query is simply discarded by the recreation. Root causes in our code: the manifest declared `android:stateNotNeeded="true"` (state saving explicitly switched off) and the programmatically-built `EditText` had **no view id** (the framework only saves/restores text for views with ids).
- **Fix (v0.3):** removed `android:stateNotNeeded="true"` from the activity in `AndroidManifest.xml`; gave the search `EditText` a stable id (`setId(1001)`); in `onResume`, re-apply `filter(searchBox.getText())` immediately and once more after 400 ms, so the grid always resyncs to whatever text the box holds even if the restore doesn't re-fire the text watcher.
- **Verified fixed:** on the final v0.3 build, portrait with query `clock` (grid = Clock only, [qa-f2-portrait-filtered.png](sandbox://workspace/tree-os/shots/qa-f2-portrait-filtered.png)) → rotate to landscape: **box still holds `clock`, grid still shows only Clock** ([qa-f2-landscape-filtered.png](sandbox://workspace/tree-os/shots/qa-f2-landscape-filtered.png)) → rotate back to portrait: same state preserved ([qa-f2-portrait-back.png](sandbox://workspace/tree-os/shots/qa-f2-portrait-back.png)).

### BUG-3 (a) launcher source, aggravated by (c) emulator slowness — MODERATE — Launcher ANR on rotation on the heavy iteration image
- **Observed once:** on TreeOS_Phone (API 37 Play Store image, swiftshader) with v0.3 build 2, rotating the home screen raised **"TreeOS isn't responding"** ([qa-final-landscape-filtered.png](sandbox://workspace/tree-os/shots/qa-final-landscape-filtered.png)); the app recovered via "Wait" (pid unchanged afterwards, FATAL_COUNT=0, no `ANR in dev.treeos.launcher` trace lines beyond the dialog event). System UI ANR'd the same way twice on the same device in the same period (OBS-3) and never on the API 35 image — the trigger is main-thread saturation during rotation on a software-rendered, Play-Services-loaded image.
- **Our contribution (the fixable part):** every activity recreation re-ran the full app load on the main thread — `queryIntentActivities` + `loadLabel` + `loadIcon` for every launcher app — the heaviest work in the app, repeated on every rotation.
- **Fix (v0.3):** the app list (labels + icons) is built once per process into a static cache (`cachedApps`); recreations reuse it and skip the PackageManager/icon work entirely.
- **Verified improved:** with the final build, the identical rotation sequence on the same device (query in place, portrait→landscape→portrait) ran with **no ANR dialog in either rotation, zero `ANR in dev.treeos` logcat lines, FATAL_COUNT=0, and a stable pid (1974)**. Honest caveat: this is a small sample on an emulator whose load varies; the fix removes our known main-thread cost from the rotation path, which is the part we control.

### Observations (not fixed; not launcher defects)
- **OBS-1 (c) stock behavior:** in the "No apps match" state the dock rides up directly under the empty-state text, leaving a large blank area below (the empty GridView measures to zero height and the linear layout collapses upward). It reads as intentional and the message + dock stay reachable; left as-is.
- **OBS-2 (c) by design:** dock buttons have no long-press action (grid cells open App info; dock buttons don't). Consistent with the dock being shortcuts, not app cells; noted for a future UX decision, not changed.
- **OBS-3 (c) emulator environment:** on TreeOS_Phone only, **System UI** raised "isn't responding" twice during rotations (swiftshader + Play Store image load). Never on TreeOS_Image, never involving our process's code path. No action.
- **OBS-4 (c) fresh-image stock behavior:** Chrome (grid and Web dock) lands on Chrome's first-run screen on a wiped image because Chrome was never set up; after first-run, the Web dock intent loads `https://example.com` as coded.
- **OBS-5 (test-environment note):** first cold boot of the wiped image takes ~4–5 min to `boot_completed` under swiftshader; the Razer reports `mPlugType=0`, so `stay_on_while_plugged_in` does nothing there — QA scripts must use `svc power stayon true` (runtime-only, re-apply after every reboot) or the screen sleeps mid-test and screenshots come back black (15,580-byte frames).

### Suspected bugs that evidence cleared (kept for the record)
Two initially-suspected launcher bugs were **harness artifacts**, proven not to exist — recorded so nobody re-chases them:
- **"BACK doesn't dismiss the keyboard / Tree panel won't open after search"** — FALSE. With the search box focused, BACK hides the IME correctly (`mInputShown=true` → `false`, query retained). The failures came from fixed adb tap coordinates: while the IME is up the window resizes and the dock moves, so a tap aimed at the keyboard-down dock position misses. With live UI bounds (or the IME down), the Tree panel opens and "Got it" dismisses it every time.
- **"Search filter desyncs from the box after rotation" (grid full, box holding query)** — FALSE as stated. The reading came from `uiautomator dump` output captured while Gboard's landscape fullscreen extraction editor was up; those dumps mix the IME's editor (which held the text) with a stale app hierarchy. Screenshot ground truth showed the real behavior — box empty + grid full — which is BUG-2 above.
- A mid-QA "everything renders ~25% smaller" scare was also a preview-scaling artifact: `wm size`/`wm density` measured constant at 1080x2400 / 420 dpi (matching the AVD config) and UI-dump bounds were pixel-identical across the "big" and "small" frames.
